# 05. 演示一次，不要解释两遍

**结果：你做完一遍它看着。流程被存下来。下次同一句话就能跑。**

## 目标

教工作流的方式是**做一遍给它看**，不是写一篇没人爱看的 SOP。吃掉你一周的活，往往描述起来又臭又长，演示起来却很短。

## 做法

挑一件同时满足这三条的任务当第一条录像：

- **至少每周一次**
- **跨两个以上工具**
- **步骤不怎么变**

例：从看板拉数字 → 对一下下降的项 → 贴进文档对应标题 → 跌幅超过 15% 就 Slack 给组长。

入口在远端桌面右上角的 teach-a-task：你接管屏幕，做一遍，交回去。下次你只说「按上周那样跑」。

Bot 会记住对话，也会记住你喜欢怎么收尾。有厂商把方向说成：它们最终会在你开口前开工。把这句话当**航行方向**，不当 beta 承诺。

## 为什么重要

跨工具、步骤稳定的例行，最不值得你每周重新解释。演示把「不可言说的手感」变成可回放的动作；纯文字说明会漏掉你点了哪个过滤、哪个标题、哪个人。

## 反例

- 第一次就录一个月才做一次、每次界面都变的流程。它学会的是这一次的偶然。
- 只在聊天里写 20 步，却不让它看见真实页面。漏掉的点击会变成自信的错操作。
- 演示完不改章程、不补停线。它学会了「怎么点」，没学会「什么不能点」。
