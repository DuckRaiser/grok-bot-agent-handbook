# 03. 工具只连一次

**结果：Gmail / GitHub / Slack 在账户层连好。第五个 bot 不用再走一遍授权。**

## 目标

插件面板里把常用工具接上，而且要尽早接。连接挂在**账户**上，不是挂在单个 bot 上。

面板里常见：Notion、Slack、Google Drive、AWS Agents、AWS SageMaker、Browserbase、Composio、Context7，以及自定义项。

## 做法

1. 打开插件 / 连接面板，先连你**这周就会用到**的账号。
2. 连一次 Gmail 或 GitHub，之后每个 bot 都能用。同一个连接器也可以挂多个号（工作邮箱 + 个人邮箱），不必再找第二个插件。
3. 第五个专家上岗时，生产力来自「已经连过」，不是来自再写一遍授权说明。
4. 测试阶段只连真正需要的号。爆炸半径 = 你以后会建的每一个 bot。多号共用同一个连接器时，爆炸半径更大，私人号和工作号要有意识地分开授权给谁。

顺序建议：先连核对第一份小任务要用的那一个（日历、邮箱或 Notion），再扩。

## 为什么重要

专家模型的前提是共享工具、分离记忆。工具不共享，每个 bot 都是新员工入职；工具乱共享（连了私人号、连了不该连的生产账号），一个人犯错会变成全员犯错。

## 反例

- 每个新 bot 再走一遍 OAuth。「我不确定这个需不需要」——账户级连接意味着它已经能碰到。
- Beta 期间把个人邮箱、公司生产 AWS、家人共享盘一起插上。后面删连接比现在克制贵得多。
- 把「能连」当成「该连」。没有章程的 bot 加上全权限插件，是在放大错误，不是放大产能。
